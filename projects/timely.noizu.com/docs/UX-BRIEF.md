# Timely UX Brief

## Product Positioning

Timely is an evidence-backed time tracking system for complex, interrupt-driven work. Its product promise is accurate time without pretending work is linear: overlapping tasks, screenshots, idle gaps, resumption events, and review confidence are first-class concepts.

## UX Principles

1. Evidence without surveillance - show users what is captured and give them control before asking for trust.
2. Intervals over timers - model time as editable, overlapping intervals rather than a single active stopwatch.
3. Review beats recall - let users correct from screenshots, app context, and prompts instead of memory.
4. Confidence is visible - distinguish verified, inferred, manual, private, disputed, and approved time.
5. Fast correction path - timeline review must be keyboard-friendly and dense without becoming visually noisy.

## Primary Workflows

### First Run

1. Create workspace.
2. Install desktop agent.
3. Grant permissions.
4. Review policy summary.
5. Create first client/project/task.
6. Run capture test.
7. Start tracking.

### Daily Capture

1. Start or infer task.
2. Capture screenshots and context.
3. Detect app, URL, idle, sleep, and resume events.
4. Prompt only when a decision is useful.
5. Buffer offline events locally.

### Daily Review

1. Open day timeline.
2. Resolve idle gaps and low-confidence intervals.
3. Split, merge, reassign, or mark overlaps.
4. Delete or redact sensitive evidence.
5. Submit or lock reviewed time.

### Billing

1. Filter approved client/project time.
2. Select screenshot evidence level.
3. Review totals and confidence warnings.
4. Export CSV/PDF or share report link.
5. Mark invoice state.

## Recommended Style Direction

Minimal Tech 80%, Editorial 20%. Timely should feel calm, precise, and serious, with dense operational surfaces. Avoid playful surveillance metaphors, giant marketing hero layouts, and decorative dashboard cards that make the timeline harder to scan.
